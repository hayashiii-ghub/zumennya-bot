# zumennya-bot · 図面帳

図面から拾った仕上げの候補を、根拠・照合・レビュー・判断の記録といっしょに見る場所。作業はチャットのボット（Grok Bot）が行い、このアプリは記録を保存して見せる。サイトと Grok Bot で一つの道具になるよう、画面は「見る」ことに絞る。

公開デモです。ログインはなく、誰でも見られます。中身はすべて架空のデモで、本物の図面や顧客の資料は入れません。書き込めるのは、鍵を持つボットの API だけです。

## 役割

| ボット     | していること                                                         |
| ---------- | -------------------------------------------------------------------- |
| おやかた   | 人との窓口。報告と承認の依頼、判定・保留の記録、判断パターンの記憶   |
| ひろいだし | 図面を読み、候補・根拠・根拠画像を入れる                             |
| かたろぐ   | カタログの登録・改訂・廃番、品番の照合                               |
| かくにん   | 原本と根拠画像だけを見て独立にレビューし、指摘を追記する             |
| かきだし   | Drive とシートへ書き出し、書き出しを記録する（最終版は全件の判断後） |

ボットは [API](docs/bot-api.md) だけで書き込む。鍵は1つで、どのボットかは申告。人の判定はチャットで受けたものを、おやかたが名前つきで記録する（本人確認はしていないと画面に出す）。

全体の流れは [システムの流れ](docs/system-flow.md) にまとめています。

## 置き場所

| 置き場所     | 内容                                                                     |
| ------------ | ------------------------------------------------------------------------ |
| Google Drive | 原本（図面・カタログ）と、書き出したシート                               |
| D1           | 状態と履歴の正本。追記だけで、承認の決まりはトリガーで止める             |
| R2（非公開） | 図面から切り出した根拠画像。バケットは公開せず、このアプリを通して見せる |

## 画面

画面は2つだけ。案件をまたいだ調べもの（品番がどの案件で使われているか、判断パターンの一覧など）は、おやかたに聞く。

- `/` 案件一覧（進み具合と、あなたの番・待ち・ボットの番・重大な指摘の件数）
- `/p/<案件>` 案件の看板。列は「いま誰の番か」で分ける。上に、最新の書き出し（版・最終版か作業版か・確かめた結果・シート）を出す

| 列         | 入る候補             |
| ---------- | -------------------- |
| ボットの番 | 未レビュー、重大あり |
| あなたの番 | 承認待ち、要確認     |
| 待ち       | 保留                 |
| 決定       | 承認済み、対象外     |

列は最初は閉じていて、見出しを押すと開く（件数は閉じたままでも見える）。カードを押す（`?c=C-006`）と、そのカードの列は開いた状態で、PC では右に、スマホでは全画面で、根拠・照合・レビュー・判定と保留・版の履歴が開く。案件全体の動きや参考情報（下地など）は画面に出さず、記録と API に残す。カードを人が動かす操作はなく、列はボットの記録と DB の決まりで動く。

## 手元で試す

```sh
bun install
cp .dev.vars.example .dev.vars
bun run db:local
bun run dev   # http://localhost:5173
```

確認が済んだらサーバーを止める。

## 検証

```sh
bun run test          # 型の生成 → 型チェック → テスト（隔離した D1/R2）
bun run format:check
```

画面を変えたら、スマホ幅と PC 幅の表示も確かめる。

## 公開

cf は公開前のベータ版。

1. `bunx cf auth login`
2. `bunx cf d1 create zumennya-bot` で D1 を作り、`cloudflare.config.ts` の ID を置き換える
3. `bunx cf r2 buckets create` で `zumennya-bot` のバケットを作る（公開の設定はしない）
4. `bunx cf d1 migrations apply <D1 の ID>`（`--local` なしで本番に適用）
5. `bun run deploy`
6. 秘密値 `BOT_API_KEY`（新しく作る）を Worker に登録する
7. 公開先の URL と `BOT_API_KEY` は Grok Bot に別に渡す。URL はこのリポジトリに書かない。鍵は秘密値の入力欄から渡し、チャットに貼らない。

画面には Drive とシートのリンクが出る。共有の設定は変えず、誰でも見られる設定にしない（持ち主の名前が見えるため）。公開したいときは、デモ専用の Google アカウントに置く。

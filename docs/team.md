# 図面屋さん（ずめんや）

Grok Bot 5体のチーム。図面から内装の仕上げ一覧を作る。記録の正本は zumennya-bot の API（Cloudflare Workers ＋ D1）。承認は必ず人が行う。原本の図面は誰も変更しない。

合図はグループチャット「ずめんや」で行う。API の呼び出し方は [ボット向け API](bot-api.md)、記録が画面に出るまでの流れは [システムの流れ](system-flow.md)。

## おやかた（窓口・まとめ役）

判断が必要な候補を、根拠・選択肢・おすすめを付けて人に1回でまとめて聞き、返事を判定・保留・新しい版として記録する。全件が決まったらかきだしに書き出しを指示する。

- Skill：人に聞くときの判断基準（ASK_RULES）、API での判定記録、進捗とタスクの整理

## ひろいだし（図面の読み取り）

Drive の図面（PDF・スキャン）を読み、部屋・部位・仕上げ・品番の候補を根拠と根拠画像付きで登録する。読めない値は推測せず「要確認」にする。

- Skill：図面読み取りの手順（EXTRACT_RULES）、図面の版の管理、根拠画像の切り出しと登録

## かたろぐ（カタログ照合）

建材カタログを版ごとに登録し、廃番も管理する。候補の品番をカタログと照合し、一致・不一致・照合保留・未登録・品番なしに分ける。名前が似ているだけでは確定しない。

- Skill：カタログ照合の手順（CATALOG_RULES）、廃番と後継品番の管理

## かくにん（独立レビュー）

ほかのボットの説明は使わず、原本と根拠画像だけで候補を確かめる。指摘には重大か軽微を付け、直った版を確かめてから閉じる。

- Skill：レビュー基準（REVIEW_RULES）、版をまたいだ差分の確認

## かきだし（最終版の書き出し）

全件が決まってから、仕上げ一覧の最終版を Google スプレッドシートと xlsx に書き出す。API と全件突き合わせて、一致したときだけ記録する。変更があれば上書きせず版を上げる。

- Skill：書き出しと突き合わせの手順（EXPORT_RULES）

## 流れ

ひろいだし → かたろぐ → かくにん → おやかた → 人の承認 → かきだし
